# Этап 0: инструкция приёмочного тестирования

Этот тест подтверждает только исследовательский прототип Stage 0. Он не подтверждает захват базы, автономный игровой цикл или функции этапа 1.

## Предусловия

Перед тестом запишите:

- версия Arma Reforger: `________________`;
- версия Reforger Tools: `________________`;
- ветка/тег: `________________`;
- commit (`git rev-parse --short HEAD`): `________________`;
- дата и время: `________________`;
- тип запуска: `listen server / dedicated server`;
- тестировщик: `________________`.

Должны быть выполнены условия:

1. Игра и Tools установлены на одной стабильной версии. Целевая версия текущего кода — 1.7.0.54.
2. Репозиторий находится в доступном для записи локальном каталоге, не в Workshop и не в OneDrive.
3. Workbench Launcher видит `ArmaReforger`, `AIConflictCore` и `AIConflictArland`.
4. Через Workbench Launcher открыт проект `AIConflictArland`.
5. Resource Database закончил обновление.
6. `Build → Validate Scripts` и `Build → Compile and Reload Scripts` выполнены без ошибок.
7. Для запуска используется штатный `{C41618FD18E9D714}Missions/23_Campaign_Arland.conf` (`Conflict - Arland`).
8. В списке активных модов виден `AI Conflict Arland` с GUID `B52C5F6AEDBF423E`.
9. AI не отключён; для dedicated server `operating.disableAI=false`, `operating.aiLimit=-1` либо установлен достаточный положительный лимит.

Если хотя бы одно предусловие не выполнено, отметьте тест как `BLOCKED`, а не как `FAIL` реализации.

## Пошаговый тест

### Часть A. Workbench

1. Запустите Reforger Tools и выполните `Add Project → Scan for Projects` для корня репозитория.
2. Сделайте скриншот списка из трёх проектов.
3. Откройте `AIConflictArland` и дождитесь окончания Resource Database.
4. Откройте `Editors → Script Editor`.
5. Выполните `Build → Validate Scripts`; сохраните полный текст результата.
6. Выполните `Build → Compile and Reload Scripts` (`Shift+F7`); сохраните полный текст результата.
7. Если есть хотя бы одна script/dependency/resource error, остановите игровой тест и зарегистрируйте дефект компиляции.

### Часть B. Listen server

1. Закройте ранее запущенную игру.
2. Запустите `ArmaReforgerSteam.exe` с корнем репозитория и GUID Arland-аддона:

   ```powershell
   & "<Steam>\steamapps\common\Arma Reforger\ArmaReforgerSteam.exe" -addonsDir "<абсолютный путь>\Arma-Reforger-AI-Conflict" -addons B52C5F6AEDBF423E
   ```

3. Выберите `Multiplayer → Host → Host new server`.
4. Выберите `Conflict - Arland` и убедитесь, что в Mods присутствует `AI Conflict Arland`.
5. Запустите сервер. Не требуется выбирать фракцию или создавать персонажа.
6. Запишите точное время появления мира и ждите 35 секунд.
7. Откройте последнюю папку `%USERPROFILE%\Documents\My Games\ArmaReforger\logs`.
8. Найдите все строки `[AICF][STAGE0]`, не удаляя соседний контекст.
9. Сосчитайте `GROUP_CREATED` отдельно для `faction=US` и `faction=USSR`.
10. Проверьте итоговую строку результата.
11. Сохраните полную папку логов и, если группы видны наблюдателю, сделайте скриншот или короткое видео.

### Часть C. Проверка идемпотентности

Обычный запуск не обязан повторно вызывать `OnGameStart`. Проверка выполняется без изменения мира:

1. Просмотрите журнал всей одной сессии.
2. Допустима строка `BOOTSTRAP_DUPLICATE_SKIPPED`, если движок повторно запросил инициализацию.
3. В любом случае в одной сессии должно быть ровно по одному успешному `GROUP_CREATED` для `US` и `USSR`.
4. Перезапуск новой сессии создаёт новую пару групп и не является дубликатом.

Не редактируйте скрипт и не вызывайте protected-методы вручную ради этой проверки.

## Ожидаемые диагностические сообщения

Обязательный успешный минимум:

| Событие | Сколько | Что подтверждает |
|---|---:|---|
| `BOOTSTRAP_SERVER` | 1 | код выполняется authoritative server/master |
| `CONFLICT_READY` | 1 | штатный Conflict и base manager готовы |
| `BASE_DISCOVERY` | 1 | обнаружены штатные objectives и graph nodes |
| `GRAPH_NODE` | по одному на узел | состав графа выведен |
| `GRAPH_EDGE` | по одному на ребро | направленные связи выведены |
| `GRAPH_SUMMARY` | 1 | итоговое число узлов/objectives/рёбер |
| `FACTION_READY faction=US` | 1 | получена штатная BLUFOR/US |
| `FACTION_READY faction=USSR` | 1 | получена штатная OPFOR/USSR |
| `TARGET_SELECTED faction=US` | 1 | США получили допустимую graph-reachable цель |
| `TARGET_SELECTED faction=USSR` | 1 | СССР получил допустимую graph-reachable цель |
| `GROUP_CREATED faction=US` | 1 | создана группа США |
| `GROUP_CREATED faction=USSR` | 1 | создана группа СССР |
| `WAYPOINT_ASSIGNED faction=US` | 1 | waypoint США назначен |
| `WAYPOINT_ASSIGNED faction=USSR` | 1 | waypoint СССР назначен |
| `GROUP_READY` | 1 | обе группы имеют бойцов и назначенные waypoint |
| `[RESULT][PASS]` | 1 | все проверки Stage 0 внутри сценария успешны |

Сообщения ожидания `BOOTSTRAP_WAIT_CONFLICT`, `BOOTSTRAP_WAIT_BASES` и `GROUP_VERIFY_WAIT` допустимы. `GRAPH_SOURCE_RADIO_MISSING` или `GRAPH_DISCONNECTED` — предупреждения, которые нужно приложить к отчёту; успешность зависит от найденных целей и финального результата.

Любое `[ERROR]` или `[RESULT][FAIL]` делает тест неуспешным. Не заменяйте конкретную ошибку общим описанием «не работает».

## Известные ограничения

1. В среде разработки этого коммита нет Reforger Tools; успешная компиляция и runtime не заявлены.
2. Нет отдельного scenario-resource: тест вручную запускает официальный Conflict - Arland. Это сознательно исключает копию штатного мира.
3. Scripts-only bootstrap сработает в любом `SCR_GameModeCampaign`, если Arland-аддон ошибочно загрузить в другом Conflict-сценарии; тестировать следует только Arland.
4. Граф — snapshot штатной radio reachability при старте. Изменения сигнала после запуска в этапе 0 не перестраивают граф.
5. `BASE` и `SOURCE_BASE` являются целями; принадлежащий стороне `RELAY` может быть транзитным узлом. Нейтральный и вражеский relay не используется как транзит даже при наличии физического radio-edge.
6. `IsValidTarget()` и radio-edge не доказывают существование пешеходного navmesh-маршрута. Прибытие и захват относятся к этапу 1.
7. Группы берутся из штатного `GetDefendersGroupPrefab()`. Пустой/повреждённый ресурс штатной фракции завершает тест явной ошибкой; альтернативный выдуманный prefab не используется.
8. Используется штатный Move-waypoint `{750A8D1695BD6998}Prefabs/AI/Waypoints/AIWaypoint_Move.et`, проверенный для 1.7.0.54; после обновления игры ресурс нужно проверить заново.
9. AI limit, `disableAI`, моды сервера и изменения vanilla-конфигурации могут помешать появлению бойцов. Сторонние моды в эталонном тесте запрещены.
10. После ошибки инициализация в этой сессии автоматически не повторяется, чтобы не создать дубликаты. После исправления причины начните новую сессию.
11. Этап 0 не проверяет движение до цели, бой, захват, подкрепления, билеты, победу или баланс.
12. Защита от дубликатов относится к повторному входу в один экземпляр GameMode. Восстановленная persistent-сессия не имеет стабильной метки тестовых групп; используйте новый listen host либо `-backendFreshSession` для dedicated-теста.
