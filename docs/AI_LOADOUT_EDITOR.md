# Редактор экипировки ИИ

Реализация предложения из [AI_LOADOUT_EDITOR_FEASIBILITY.md](AI_LOADOUT_EDITOR_FEASIBILITY.md).
Дата проверки: 2026-09-18. Реализованы форма, серверная библиотека и выдача
следующим бойцам. Visual и полная multiplayer/gameplay-матрица ещё не проверены;
результат не объявляется ACCEPTED.

## Использование

1. На карте откройте **«Экипировка»**. Вверху редактора выберите отряд из списка
   своей фракции: например, **«Отряд 1 — A0»** или **«Отряд 7 — D0»**. Номер
   остаётся постоянным при смене роли отряда. Возвращаться на карту для смены
   отряда не нужно; при первом открытии выбран текущий отряд командной панели.
2. Выберите позицию бойца, включая ещё не набранную. Позиция соответствует
   исходной роли roster; редактор не меняет состав, лицо или голос.
3. Слева находится кукла, в центре — компактный список мест экипировки,
   справа — каталог фракции с превью и поиском по текущему месту. Прокрутка
   работает колесом над карточками и кнопками «Выше»/«Ниже», которые видны
   только если список не помещается на одну страницу. Одежда и оружие находятся
   в одном основном списке. Выпадающего списка контейнеров нет: двойной клик
   по надетой вещи, оружию или вложенному подсумку открывает его содержимое.
   Заголовок называет текущий предмет; «Назад» возвращает на уровень выше
   и выделяет его в родительском списке. Несколько native storages одного предмета
   показаны на общей странице, но каждая операция сохраняет точный адрес storage.
   Пустые служебные storages не открывают пустую страницу.
   Над списком показаны занятый/полный объём в литрах, процент заполнения и
   свободный объём. На бойце это карманы выбранного контейнера; внутри —
   текущий открытый контейнер. Показания обновляются после изменения черновика.
4. Выберите место в центре: каталог автоматически следует за фокусом.
   Для мест надевания и оружейных креплений справа показана подпись «Подходит: …».
   Внутри контейнера вместо неё появляется фильтр категорий: все предметы,
   боеприпасы, гранаты и дым, медицина, снаряжение, обвесы, оружие, одежда и
   контейнеры. Поиск по названию работает совместно с категорией; «Очистить»
   появляется при активном фильтре и очищает оба фильтра. Категория запоминается при переходе между контейнерами;
   выбор другого предмета в том же контейнере сохраняет поиск и прокрутку.
   Пустой слот головного убора также предлагает головные уборы; бронежилеты и
   разгрузки разделены на две категории по native компоненту одежды, хотя stock
   arsenal объединяет их одним типом `VEST_AND_WAIST`. Выберите предмет справа и нажмите
   «Надеть», «Заменить» или «Добавить» — подпись соответствует действию.
   Двойной левый клик по карточке каталога выполняет то же действие для
   выбранного места. Одинарный клик только выбирает предмет.
   Правая кнопка мыши по вещи в основном списке снимает её, а внутри контейнера
   убирает выбранный предмет вместе с его содержимым из черновика. «Отменить шаг»
   возвращает удалённое. Двойной клик только открывает содержимое и ничего не
   удаляет. Кнопки «Содержимое» и «Снять»/«Убрать» удалены; подсказка под списком
   объясняет доступные действия. Пустое место и строка добавления на ПКМ не реагируют.
   Оружейные места имеют понятные названия: основное, дополнительное основное,
   кобура и гранаты. Кобура показывает оружие native типа `secondary`, а не
   автоматы `primary`. Как штатный Inventory20, редактор скрывает служебное
   пятое оружейное место. Тип определяется компонентом слота, не его номером.
   Места на оружии называются «Прицел», «Штык», «Дульное устройство»,
   «Подствольный обвес» и «Магазин». Каталог проверяет native совместимость
   именно с выбранным креплением, включая замену уже установленного предмета.
   Место магазина предлагает совместимые боеприпасы. Служебные крепления,
   скрытые в штатном осмотре оружия, скрыты и здесь.
   Для выбранного оружия и внутри его обвесов над центральным списком появляется
   **«+ Магазин»**: один клик добавляет один совместимый запасной магазин в
   свободный карман бойца, включая вложенные подсумки RHS. Рядом показана общая
   вместимость карманов. Сначала проверяется такой же магазин, как заряжен,
   затем штатный и остальные разрешённые магазины каталога фракции. Совместимость
   определяется native `MagazineWell`, вместимость — native проверкой storage.
   Заряженный магазин не меняется. Сообщение называет добавленный предмет и
   контейнер; при отсутствии подходящего магазина или места объясняет отказ.
   Действие отменяется через «Отменить шаг» и вступает в силу после сохранения
   комплекта. Количество каталога на эту кнопку не влияет: каждый клик даёт +1.
   Строка «+ Добавить в контейнер» использует количество 1–16; отдельной
   дублирующей кнопки нет. Счётчик и кнопки количества видны только для этой
   строки. Конкретное место меняет один предмет. На время запроса сервера
   действия отключаются. Каталог
   контейнера **не зависит от свободного места**: несовместимость и вместимость
   проверяются при применении и повторно сервером. Для экипируемых мест ручного
   переключателя категорий нет.
   Контейнер предлагает каталог вещей, а места надевания — свой тип одежды
   или оружия. Тип слота не определяется наличием свободного места.
   Вращайте куклу с зажатой ЛКМ, меняйте масштаб колесом. Зажмите колесо и
   перемещайте мышь вверх/вниз для вертикального перемещения камеры, в том числе
   при приближении. Высота камеры сохраняется при замене предметов;
   подсветка остаётся направлена на модель. Ресурсы головы/тела куклы сохраняются
   между пересборками одного исходного персонажа, включая смену шапки и откат.
   «Отменить шаг» снимает
   последнюю операцию, «Стандартный» возвращает исходный комплект.
5. Укажите имя длиной от 1 до 80 символов и нажмите **«Сохранить»**. Это единственная
   кнопка с ярким акцентом; она доступна только при изменении экипировки или
   имени. Без изменений показана неактивная подпись «Без изменений»; неверное
   имя и несовпадающая server revision не допускают отправку. Только ответ сервера `SAVED`
   означает запись. Отмена/закрытие карты не сохраняет черновик.

Шаблон назначается `stable faction + numeric slot + memberIndex` в текущей
кампании. Его получает **следующий созданный боец** этой позиции: начальный
deployment, replacement или recruitment. У пехоты начальный deployment содержит
одного бойца; остальные получают свои комплекты при наборе в казармах.
Экипировка уже живых бойцов не меняется.

При переключении отряда открывается его командир и запрашивается отдельный
server snapshot. Количество позиций соответствует выбранному отряду. Сообщение
после сохранения называет отряд и позицию; назначение не распространяется на
командиров других отрядов. Несохранённые черновики запоминаются раздельно по
отряду и позиции до закрытия редактора. При возвращении они восстанавливаются,
если server revision не изменилась; при конфликте загружаются актуальные данные
с пояснением. Закрытие формы очищает эту временную память.

Союзники могут редактировать свои общие позиции. При конфликте ревизий сервер
отклоняет запись, форма сохраняет локальный черновик и требует повторного
открытия позиции. Переход в другую фракцию/персонажа закрывает форму. Библиотечный
шаблон сначала открывается как черновик; назначение требует «Сохранить».

## Владельцы и ограничения

### Упрощение интерфейса — 2026-09-17

При ревью по коду устранены следующие проблемы взаимодействия:

| Проблема | Изменение |
|---|---|
| Несколько кнопок ведут к одному выбору | Убраны «Одежда», «Оружие» и отдельная «+ Добавить»; остаются список мест и строка добавления в контейнер |
| Лишние кнопки дублируют работу со списком | Вход по двойному клику, удаление по ПКМ; возврат, количество и очистка фильтров появляются по контексту |
| Все действия выглядят одинаково важными | Яркий акцент только у доступного сохранения; вторичные и отключённые действия визуально различаются |
| «Сбросить» и «Сброс» обозначают разные операции | Названия разделены: «Стандартный» для исходной экипировки, «Очистить» для фильтров |
| «Назад» неоднозначно обозначает страницу или контейнер | Страницы используют «Выше»/«Ниже», возврат из контейнера — «Назад» |
| Кнопка сохранения создаёт новую версию без изменений | Изменения и имя проверяются до RPC; сравнение использует кэш сериализации после Rebuild |

В форме остаются основной список экипировки, каталог и контекстные подсказки.
Кнопки страниц показываются только при переполнении списков. «Надеть»/«Заменить»
сохраняет явную альтернативу двойному клику по каталогу.
«Загрузить» сохраняет явное применение выбранного шаблона к черновику.
Автосохранения и смены серверного комплекта при навигации нет.

Ревью расположения выполнено по source anchors и состояниям widgets. Это не
визуальный verdict: читаемость в игре, доставка событий мыши и FPS требуют
ручной проверки. Терминальные gates перечислены в [TESTING.md](TESTING.md).

### Границы ответственности

| Владелец | Обязанность |
|---|---|
| `AICF_LoadoutEditor` | Программная форма, локальный черновик, input lifecycle |
| `AICF_LoadoutItemGrid` | Прокрутка карточек и native item previews только для видимых элементов |
| `AICF_LoadoutNavigation` | Дерево предметов, общие страницы storages, точные адреса операций, возврат и суммарная вместимость карманов |
| `AICF_LoadoutSlotView` | Название и категория места из native LoadoutArea, включая пустое место; объём контейнера по native storage |
| `AICF_LoadoutPreview` | Визуальная копия черновика, отдельный `InspectionPreview` world, камера, штатная сцена inventory и заполняющий `LightEntity` |
| `AICF_LoadoutRpc` / `SCR_PlayerController` | Player-owned intent, token, rate limit, OwnerOnly `RplProp` snapshot |
| `AICF_LoadoutService` | Проверка server context, профиля, стороны, исходного персонажа, ревизии и рецепта |
| `AICF_LoadoutCatalog` / content profile | Enabled faction ITEM entries с `SCR_ArsenalItem`; дедупликация RHS |
| `AICF_LoadoutInventory` / `AICF_LoadoutDraft` | Изолированный in-memory preview world, inventory adapter и readback |
| `AICF_LoadoutStore` | Неизменяемые файлы шаблонов, readback перед подтверждением |
| `AICF_GroupSlot` | Binding по позиции, ревизия и снимок ревизии deployment |
| `AICF_LoadoutApplicator` | Проверка конкретного ИИ после randomizer, выдача и сравнение результата |
| Recruitment / Economy | Readiness, оплата, transfer и штатный rollback |

RPC не принимает цену, faction authority, entity ID или stock inventory JSON.
Сервер заново определяет игрока и его сторону. Рецепт содержит максимум
48 операций, глубину до 6, до 16 предметов в операции, payload до 24576 символов.
Имя ограничено 80 символами. Предметы берутся из активного faction/content
каталога; техника, стационарное вооружение, мины/взрывчатка и support stations
не входят в редактор. Проверяется наличие основного оружия и боеприпасов
к установленному оружию. Это не доказательство использования каждого предмета ИИ.

Вложенные адреса состоят из component class, source GUID и slot index. Сырой
inventory snapshot создаёт только сервер после сборки и проверки рецепта.
Adapter использует inventory-часть stock serializer, исключая character labels,
лицо, голос и active weapon metadata. Перед выдачей другому concrete prefab
после randomizer проводится независимая проба; несовместимость отклоняется.
На каждом этапе результат читается обратно и сравнивается с ожидаемым.

Порядок `GetAgents()` не используется как позиционная идентичность:
`AICF_LoadoutMemberIdentity` фиксирует ровно одного добавленного бойца в stock
`SpawnGroupMember(index, res)` boundary. Новая группа получает новый generation,
сохраняя slot/bindings. Смена шаблона во время spawn отменяет старую выдачу;
readiness и очередь stock spawn сохраняются.

Изолированные preview entities никогда не меняют inventory живого персонажа.
Для локальной сборки используются `CanInsertResourceInStorage` и `AttachEntity`;
native inventory tasks в preview world не выполняются. Для изображения используется
`InventoryItemComponent.CreatePreviewEntity` в отдельном мире формы. `RenderTargetWidget`
показывается только после `SetWorld`, ограничен 30 кадрами/с и не рендерит кампанию
при ожидании данных. Вращение меняет только камеру, без пересборки персонажа;
при неподвижной мыши обновления камеры нет. Освещение задаёт штатный
`InventoryPreviewWorld.et` в собственном мире формы. Его entity сохраняется до
закрытия. `LightHandle` нельзя хранить в полях: compiler допускает native pointer
только как локальную переменную. Эксперимент с такими полями отозван после
ручного обнаружения пропавшего изображения.

Дополнительная подсветка использует штатный dynamic prefab
`{106CAFF367CA4BCC}Prefabs/Editor/Common/CameraLight.et`, созданный через
`SpawnEntityPrefabLocal` именно в мире формы. Это сохраняемый `LightEntity`,
не native pointer. Нейтральный заполняющий свет без теней и specular расположен
перед моделью со стороны камеры и немного выше центра; он поворачивается вслед
за ракурсом. Дистанция до центра постоянна, поэтому zoom и пересборка комплекта
не меняют положение света относительно центра. Позиция и направление задаются
одним `SetWorldTransform`, как у штатного dynamic camera light. Для spot нельзя
ограничиваться проверкой перемещения: его forward должен смотреть на центр модели.
LV снижен с prefab 13.37 до 6.5,
радиус — с 200 до 8 м. HDR, ambient и postprocess штатной сцены сохранены.
Если prefab недоступен или создался в неверном мире, дополнительная сущность
очищается, логируется `fill_light=UNAVAILABLE fallback=STOCK_LIGHTING`, а
персонаж остаётся на штатном свете. Первый вариант с LV 3.5 и отдельными
`SetOrigin`/`SetLightDirection` получил ручной **FAIL**: пользователь видел свет
со спины, не следующий за камерой. Текущий вариант с полным transform и LV 6.5
требует нового ручного verdict; компиляция/положение entity не доказывают изображение.

Закрытие формы сначала удаляет widget, затем модель, подсветку, сцену освещения и мир;
listeners, combo callbacks и timer вращения снимаются явно.

Сетки содержат только 8 компактных мест экипировки и 6 крупных карточек каталога.
`ItemPreviewWidget` ограничен 5 FPS и половинным разрешением. При прокрутке
используются те же widgets; native cache неиспользуемых предметов имеет lifetime
5 секунд. Миниатюры используют штатный client-local `ChimeraWorld.GetItemPreviewManager`,
как stock inventory. В его cache передаются только prefab names; изменяемые
entities черновика там не используются. Это осознанное разделение UI thumbnail
cache и изолированного inventory draft: снимок пользователя выявил пустые/ландшафтные
RT при использовании draft manager для карточек. Bind отложен до native widget
initialization; заданы alpha blend и LDR_SRGB. При rebuild/close отложенный bind
отменяется, widgets отсоединяются от manager, общий manager не удаляется.
Отдельная кукла, её свет и изменяемый черновик сохраняют прежние собственные миры.
Палитра карточек использует `FromSRGBA`, как панель; `FromInt` давал более светлый
результат. Пользователь подтвердил отображение самих предметов после этой правки;
миниатюры получили ручной PASS. Цвета, общее удобство и FPS требуют отдельного verdict.

Для программных панелей явно задаются flags и порядок background/input/text,
а палитра повторно применяется после native initialization. Нельзя полагаться
только на аргументы `CreateWidget`: до этой правки новые панели оставались белыми.
Панель редактора находится выше input-слоя scrim; имя использует штатный
`WLib_EditBox`. Ошибка сборки preview не затирается ответом `READY` и блокирует
сохранение некорректного черновика.

## Крепления и цельная одежда

Крепления одежды (включая балаклаву на шлеме RHS) редактируются через
двойной клик по надетой вещи. Пустые фиксированные места показаны отдельно;
каталог каждого места проверяется native inventory compatibility. Такие места
не считаются карманами: у них нет добавления количества или фильтра наполнения.
Обычные карманы сохраняют категории содержимого. Core определяет крепления
по `LoadoutSlotInfo`, без зависимости от RHS-классов.

Цельный костюм, например КЛМК, доступен из областей «Куртка» и «Брюки».
Единственный предмет показывается в обоих занятых местах. При надевании
освобождаются конфликтующие области из native `GetBlockedSlots`; замена брюк
также снимает закрывающий их костюм. ПКМ, вход в содержимое и отмена учитывают
общий предмет. Бронежилеты и разгрузки сохраняют раздельные каталоги.
Перед восстановлением полного server-generated inventory snapshot исходная
одежда снимается до вставки новой: порядок stock serializer иначе мешает
выдать костюм, пока в соседнем слоте остаются прежние брюки.

### Разгрузки и вложенные подсумки

Для 6Sh117 (SL Kit) и других модульных предметов сначала показаны установленные
подсумки и свободные крепления; двойной клик открывает карманы выбранного
подсумка. Название берётся из native UIInfo, затем из каталога. Отсутствующие
ключи перевода и prefab filenames не выводятся как подписи: используется
«Подсумок» с номером места. Вместимость разгрузки суммирует объёмы её карманов;
родительский ClothNode повторно не учитывается. Категории наполнения появляются
только в карманах, каталог крепления продолжает проверять native совместимость.

Поиск дочерней страницы использует identity установленного предмета. Обход
читает GetItem выбранного native слота; произвольный первый InventoryItemComponent
на entity не используется для построения адреса. Старый общий предел 96 storages
убран, глубина ограничена контрактом recipe (6), повторы entity исключены.
Фильтрация каталога после одиночного клика отложена на 350 ms, чтобы не загружать
native previews между двумя кликами; переход, пересборка и Close отменяют callback.

## Стоимость комплекта

Создание, сохранение и выдача шаблона управляемому боту бесплатны. Каталожная
цена одежды, оружия, обвесов и содержимого не создаёт доплату supplies при
recruitment, initial deployment или replacement. В редакторе нет цен предметов;
показано «Экипировка — бесплатно». Owner snapshot и binding сохраняют нулевую
стоимость комплекта для совместимости существующего API.

Обычная цена найма по роли и базовая стоимость восстановления отряда сохранены.
Supply pacing, выбор базы и резервация replacement используют только эту базовую
стоимость. Вместимость, допустимый каталог, совместимость, оружие/боеприпасы и
проверки server authority/revision остаются обязательными. При отказе выдачи
donor/deployment очищается штатным lifecycle, а существующая резервация/частичный
платёж за бойца возвращается существующим rollback.

## Библиотека и перезапуск

Файлы: `$profile:AICF_Loadouts/template_0.json` … `template_255.json`.
Каждое изменение создаёт новую неизменяемую версию. Повторная запись точно того
же назначенного рецепта не создаёт версию. Имя пользователя не участвует в пути.
Schema 1 хранит profile, stable faction, source character, имя и массивы операций.
Binding revision относится к текущей кампании и не переносится автоматически.

При сохранении профиля файлы переживают restart. Canonical launcher создаёт
новый profile; для явного переноса используйте:

```powershell
.\tools\Start-AICFRuntime.ps1 -Role Server -Variant Stock `
  -LoadoutLibraryPath 'C:\путь\к\предыдущему\Server-profile\profile\AICF_Loadouts'
```

Параметр работает только для Server. Launcher переносит лишь canonical numeric
filenames 0–255 размером до 24576 байт, отклоняет reparse-point files, сохраняет
имена и SHA-256 в `AICF_RUNTIME_MANIFEST_JSON`. `-DryRun` ничего не копирует.
Сервер проверяет schema и совместимость при загрузке/выборе. Шаблоны stock/RHS
и разных исходных персонажей показываются раздельно. Удалённый ресурс,
переполненная библиотека или ошибка записи сохраняют прежний валидный binding.

## Проверки

Evidence находится в `.codex-runtime/loadout-editor-20260915/`: команды launcher,
manifest, exit codes, baseline/after audits, Workbench logs и полные runtime logs.
Итоговая таблица — в `RESULT.md` этого каталога и разделе редактора в
[TESTING.md](TESTING.md).

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File tools/Test-AILoadoutStatic.ps1
powershell.exe -NoProfile -ExecutionPolicy Bypass -File tools/Test-RuntimeLauncherStatic.ps1
```

`Test-AILoadoutStatic` проверяет authority, bounded payload, revision/token,
изолированные mutations, readback, lifecycle и интеграцию spawn/recruitment;
отрицательные копии намеренно удаляют важные условия. Compile проверяется
отдельно для Arland, Everon, ArlandRHS и EveronRHS.

### Терминальные runtime fixtures

`tools/fixtures/AICF_LoadoutRuntimeProbe.c` временно копируется в `Core/Loadouts`.
`-aicfLoadoutProbe 1` проверяет обе стороны, смену одежды и оружия, добавление
обвеса и двух предметов, roundtrip, библиотеку, неизвестный prefab, лимиты,
точные member indices, выдачу ИИ и новую replacement group. После теста
процесс завершает себя; `-aicfLoadoutProbeHoldSeconds 160` оставляет время клиенту.

Для полного recruitment вместе с ним временно устанавливается существующий
`AICF_InfantryRecruitmentRuntimeProbe.c` в `Core/Forces`; flags:
`-aicfLoadoutRecruitProbe 1 -aicfRecruitProbe 1`. Fixture назначает изменённый
комплект позиции медика, затем production набирает обе группы до десяти человек.

`AICF_LoadoutClientProbe.c` временно копируется в `Core/Loadouts` обоих graphs.
Client запускается через `Start-AICFRuntime.ps1 -Role Client -ServerProfileRoot …`
с `-aicfLoadoutClientProbe 1`. Проверяются настоящий owner snapshot, локальный
draft, `SAVED`, stale revision, поддельная faction и недопустимый member index.
Дополнительно проверяются визуальная копия в отдельном мире, движение камеры,
повторная сборка без замены мира и освобождение модели/света. Параметр
`-aicfLoadoutPreviewOnly 1` дополнительно сохраняет сцену между тремя callbacks
через 2/4/6 секунд, проверяет её готовность и вращает камеру без пересборки.
Для подсветки проверяются её мир, dynamic/no-shadow свойства, перемещение
вслед за камерой, неизменное положение при zoom, повторное использование
при rebuild, сохранение между callbacks и cleanup. Дополнительно читается
фактическая матрица источника: forward направлен на центр модели, источник
находится со стороны камеры при поворотах 0/90/180/270/360°, после rebuild и
между callbacks. Проверяются native типы оружейных слотов и соответствующие
каталоги US/USSR, скрытый технический слот, сохранение identity и mesh головы
при трёх сменах головного убора и после rollback. Удаление предмета проверяется
в настоящем кармане вложенного подсумка: число предметов и занятый объём должны
уменьшиться, Undo должен вернуть оба значения. ClothNode с ремнями и подсумками
не подменяет содержимое кармана в этой проверке.
Для M16A2 и AK74_GP25 проверяются native фильтрация каждого видимого места
обвеса/магазина, неизменность inventory при фильтрации, установка подходящего
кандидата и повторная совместимость занятого места для замены. Категории
содержимого сверяются с arsenal metadata обеих фракций; отдельно проверены
границы прокрутки при нечётном числе карточек.
`-aicfLoadoutClientProbeKeepOpen 1` снимает callbacks и
освобождает тестовую сцену, но оставляет клиент открытым для ручной проверки.
Актуальный verdict fixture находится в [TESTING.md](TESTING.md).
Затем он завершает клиент; этот режим не проверяет
save/stale/faction RPC. Форма и GUI fixture не открываются. После тестов все временные production
fixtures удаляются; static audit запрещает их присутствие.

### Непроверенные критерии

- Visual: внешний вид, вращение/масштаб, читаемость формы, закрытие карты и controls.
- Два одновременно редактирующих клиента, повторное подключение/JIP inventory
  и видимость изменённого ИИ у клиента; OwnerOnly snapshot проверен отдельно.
- Стрельба, перезарядка и использование каждой категории stock/RHS снаряжения.
- Fault injection частичного inventory failure, смена loadout во время реального
  recruitment callback, отсутствие supplies и длительный soak именно этой функции.

В runtime обнаружен native RPL diagnostic незарегистрированного
`SCR_CharacterDamageManagerComponent` у изолированной preview entity.
Он сохраняется в evidence как открытое ограничение; успешные functional probes
не превращают полный runtime gate в PASS. Также сохраняются stock shutdown
и известные RHS faction-init diagnostics. Ручная проверка требуется по правилам
репозитория; screenshots/GUI automation не используются.
