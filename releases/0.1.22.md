# 0.1.22

- Исправлена блокировка возрождения на базе с сохранённым пресетом после смерти, перехода в бойца своего отряда и повторной смерти на dedicated server. Переход в ИИ теперь согласован со штатными запросами проверки базы и выбора экипировки; блокировки освобождаются в правильном порядке.
- Для выбора сохранённого пресета по-прежнему нужен действующий арсенал на базе. Исправление не обходит требования постройки, штатного таймера и доступности возрождения.
- Добавлены регрессионная fixture для отдельных server/client процессов и анализатор полных логов. Fixture используется только в тестовой сборке.

Проверки и ограничения выпуска исходников:

- Профильные static-аудиты до и после исправления — PASS; baseline failures в выполненном наборе отсутствуют. `Test-SquadRespawnContracts.ps1` проверяет 32 мутации.
- Терминальный Workbench Validate/Compile production-кода для Arland, Everon, Arland RHS и Everon RHS — PASS, exit 0.
- Старый код воспроизвёл зависание при пересечении запросов. Исправленный код прошёл по 14/14 проверок на stock EveronNorth и полном Everon RHS с настоящим арсеналом, включая повторное возрождение и совпадение состава инвентаря сохранённого пресета. Все четыре финальных server/client процесса завершились с exit 0.
- В полных финальных логах нет SCRIPT E/F, ENGINE F и VM exceptions. Ошибки ресурсов, мира и других подсистем сохраняются; функциональный PASS не означает полностью чистые engine logs.
- Runtime проверялся на localhost с принудительным пересечением запросов. Установка на пользовательский удалённый сервер, WAN, JIP, ручная визуальная проверка, покупка бойца и оплата строительства через игровой интерфейс, длительный прогон и Workshop upload — NOT RUN. Git-тег отмечает выпуск исходников.
