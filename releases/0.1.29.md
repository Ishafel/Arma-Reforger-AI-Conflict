# 0.1.29

Подготовлен 15 октября 2026 года. Изменения после тега `0.1.28`.
Релизный тег `0.1.29` создаётся на итоговом commit `main` с этими
патчноутами. Публикация пакетов в Workshop выполняется отдельно.

## Изменения

- **Совместимость с WCS 8.4.** Обновлены 388 переименованных ссылок на оружие,
  прицелы, крепления и другое снаряжение по фактическим canonical именам
  ресурсов. GUID и порядок записей сохранены.
- **Запуск сценариев WCS + RHS.** Исправлена ссылка M4A1 URGI в стандартном
  пехотном комплекте и наборе вооружения FIA. После обновления WCS ресурс
  загружался по GUID, но проверка комплекта ожидала прежний полный путь.
  На целой установке это сопровождалось повторными failed previews и
  native вылетом в RHS equipment refresh. Старый source воспроизвёл вылет
  на dedicated server; тот же probe после исправления штатно завершается.
- **Сведения о зависимостях.** Уточнены проверенные версии: RHS Status Quo
  `0.16.5237`, Content Pack 01/02 `0.16.5236`; WCS преимущественно `8.4.0`,
  Attachments `8.4.1`, RU/Sounds `8.3.0`. Все зависимости входят в граф
  запуска. Для работы нужны полностью загруженные пакеты; смешение новых
  resource databases со старыми архивами не является корректной установкой.
- **Безопасное появление пехоты рядом с техникой.** Выбор места учитывает
  полные габариты ближайших машин с запасом 2 м. Это устраняет воспроизведённую
  гибель двух бойцов под оседающим штатным БТР на одной из штабных баз Everon.
- **Восстановление после ранних потерь.** Строительство казарм может продолжаться
  после завершения начальной очереди появления. Потеря отряда до готовности
  всей армии больше не создаёт цикл ожидания казармы и полного roster;
  обычная оплата пополнения сохраняется.

## Проверки и ограничения

После повторной загрузки пользователем у всех 22 внешних RHS/WCS пакетов
`corrupted=false`; 48/48 файлов 16 обновлённых WCS совпали с манифестами
по размеру и SHA-512. Все 18 графов launcher Server/Client замкнуты.
Runtime resource probe загрузил 3347/3347 ссылок, invalid=0, renamed=0.

Production WCS Arland/Everon и диагностические stages прошли terminal
Workbench Validate/Compile. Server матрица комплектов: infantry 20/20,
FIA 13/13, default player kits 2/2; cache guards, source tabs,
arsenal/heavy provider и vehicle catalogs — PASS.

Повторение на исходной штабной базе Everon подтвердило, что оба бойца
сохраняются живыми более минуты. В отдельном тесте ранней потери ИИ построил
реальную казарму, оплатил замену бойца и восстановил все 20 отрядов.
Direct-connect клиент Arland WCS + RHS загрузил все 3347 ресурсов и оба
стандартных комплекта без ошибки, server/client штатно завершились.

Полный offline набор — **62/62 PASS**, native exit 0. Параллельная матрица
всех девяти сценариев на трёх сложностях — **27/27 startup PASS**:
точные header/world/difficulty, десять готовых отрядов каждой стороны,
не менее 20 секунд после готовности и штатное завершение каждого сервера.
Итог относится к окончательному snapshot из 267 production файлов.

Полные engine logs содержат resource/RPL diagnostics и native shutdown
leaks; targeted PASS не означает полностью чистый log. Интерактивный Host UI,
JIP, визуальная проверка, длительный soak и packaged build — **NOT RUN**.
Сохраняется известный дефект редактора `INVENTORY_RESTORE_FAILED` при пустых
промежутках native slot IDs; подробности —
[LOADOUT_CONTENTS.md](../agent-notes/LOADOUT_CONTENTS.md).

Исправление связано с [issue #57](https://github.com/Ishafel/Arma-Reforger-AI-Conflict/issues/57).
Команды, полные logs, manifests и ограничения проверок — в
