# Игровые контракты

Краткое описание для игрока находится в корневом README. Здесь сохранены
технические детали, нужные при изменении поведения; точные defaults проверяй
в `Config/`, профильных классах и `tools/Start-AICFRuntime.ps1`.

## Co-op за US или USSR

Все девять сочетаний карты/контента имеют Easy/Medium/Hard для обеих сторон.
Co-op оставляет сторону людей без managed combat roster и автоматического
размещения построек, включает автономного командира противника. Строители,
заказанная доставка и казарма сохраняются. Люди проигрывают только по территории;
противник также может проиграть по билетам. Обычные сценарии сохраняют STANDARD.
Единый каталог позволяет добавлять integration без веток launcher. Подробности:
[COOP_SCENARIO.md](COOP_SCENARIO.md).

## Найм купленных в казарме бойцов

`AICF_BarracksRecruitment` в Core распространяется на STANDARD и Co-op всех
integration addons. После штатного `OnEntityRequested` он разрешает найм
бойцов заказанного игроком отделения, включая Guard с исходным `Recruitable=0`.
Server/master проверяет troop provider `CanCommandAI`, текущий controlled entity
игрока, faction map, faction группы и разрешение MatchRules.

Server-only marker принадлежит конкретной купленной группе; текущие и async
members допускаются только при совпадении parent group/faction, живом character
и отсутствии player control. Setter вызывается только при изменении флага.
Обычная охрана, строители и managed AICF roster не получают marker.
Штатные `RequestAddAIAgent`, права лидера, ownership и лимит ИИ сохраняются.
Stock лимит — 4. Снабжение и оплату выполняет native building system.
Runtime-матрица и ограничения RHS/WCS — [TESTING.md](TESTING.md).

## Стоимость штатного заказа RHS/WCS

Группы обеих сторон оцениваются по фактическому prefab roster: 50/75/100
supplies за штатную роль. Техника использует общую шкалу классов и надбавок
за оснащение. Preview, server budget, spawner и база расчёта native refund
читают одну policy. Цены автоматического AICF пополнения 10/15/20 сохраняются.
Область действия, вся таблица до/после, API boundaries и измерения:
[MENU_PRICES.md](MENU_PRICES.md).

## Начальная погода

Четыре базовых MissionHeader stock/RHS для Арланда и Эверона включают
`m_bRandomStartingWeather 1`. North, WCS и Medium/Hard наследуют настройку:
она действует во всех 81 сценарии меню и при запуске через canonical launcher.
Штатный `SCR_TimeAndWeatherHandlerComponent.SetupDaytimeAndWeather` выбирает
состояние из списка мира на authority при инициализации нового матча.
Повторное выпадение той же погоды допустимо. `m_bRandomWeatherChanges 1`
сохраняет естественную смену погоды, иначе штатный random-start включает looping.

Прямой CLI запуск сохраняет старт в 08:00, random daytime выключен, ускорение
днём 6, ночью 24. Штатная настройка часов выполняется после выбора погоды;
при старте controller/JIP повторного выбора нет. Сетевая синхронизация принадлежит
штатному менеджеру. Frontend позволяет независимо выбрать начальные часы
(ползунок 00:00–23:59 с шагом 1 минута либо random) и погоду
(random/Clear/Cloudy/Overcast/Rainy). Случайный выбор не теряет последнее точное
время; повторное нажатие возвращает его. Перетаскивание обновляет только
представление окружения и сводку, без повторного scan addons или загрузки флагов.
Одноразовая передача через reload и authority adapter штатного handler описаны
в [SCENARIO_SETUP.md](SCENARIO_SETUP.md#передача-времени-и-погоды).
Runtime probe и анализатор: [TEST_FIXTURES.md](TEST_FIXTURES.md), результаты и
ограничения проверки: [TESTING.md](TESTING.md).

## Север Эверона: состав баз и электростанция

`TownBaseKermovan` исключён из whitelist северных stock/RHS сценариев;
WCS+RHS наследует RHS North. Остались семь активных баз: два HQ и пять целей
(Сен-Филипп, Девичья бухта, Мо, Тайрон, Грабовая долина). База Кермована
не инициализируется и не входит в AI objective/radio graph; полный Эверон
не меняется. Замена у электростанции не добавляется. Штатный
`StartingPos06` у электростанции нельзя использовать как готовую замену:
`m_bIsControlPoint 1` меняет статус базы, но не добавляет механизм захвата.
Runtime от 08.10.2026 повторно показал FAIL
`CAPTURE_MECHANISM_StartingPos06` при работающих spawn point и radio graph.
Положение лагеря vanilla — `<5766.26,7.873,9625.6>`, примерно в 175 м от
`G_Powerplant`. Наличие маркера, initialized/control-point status и spawn point
не доказывает возможность захвата.

Такая замена уже была отменена commit `c1029b5`; актуальная fixture
`tests/fixtures/AICF_EveronNorthProbe.c` намеренно проверяет у каждой цели
`SCR_CampaignSeizingComponent` с положительным radius. Не ослаблять этот gate.
`SCR_CampaignCustomBase` в API 1.8.0.13 задаёт только имя, HQ/control-point flags
и radio range; поля переноса позиции или добавления компонентов нет.
Полноценный перенос требует отдельно проработать базу, capture, spawn,
building layouts и client/JIP. Собственный слой миссии потребует пересмотра
нынешней границы «только inherited MissionHeader» в AGENTS.md и ARCHITECTURE.md.
Свежие проверки и отклонённый эксперимент: [TESTING.md](TESTING.md).

## Сложность гарнизонов FIA

Девять Variant имеют по три сложности для Standard, Co-op US и Co-op USSR:
81 тонкий inherited header (27 standard + 54 Co-op).
Прежние ресурсы сохраняют GUID. Standard Medium/Hard наследуют базовый header
с `m_eAICFDifficulty` 1/2; default 0 сохраняет лёгкий вариант. Новые Co-op
наследуют соответствующий Standard той же сложности; старый Stock Co-op USSR
сохраняет свою исходную inheritance chain.
Launcher `-Difficulty Easy|Medium|Hard` выбирает header для любого Variant,
а не переопределяет игровую сложность отдельным CLI. Зависимости не расширены.

На Medium/Hard `AICF_Difficulty.GetInfantryRoleIndex` назначает позиции
`memberIndex` 3, 8 и 9 противотанковыми во всех profiles. Stock использует native
US `LAT` / USSR `AT`, RHS/WCS — MSV `AT` у USSR и USMC `LAT` у US. Позиции 8/9 заменяют
помощника ПТ и стрелка; численность остаётся 10. RHS resolver
выбирает комплектный native prefab и его боезапас: US — M72A3 с одним выстрелом,
USSR — РПГ-7 с одним заряженным и двумя запасными. WCS заменяет M72 US
на Carl Gustaf по правилу ниже, вторичное оружие РФ сохраняет.
Один boundary `BuildCharacterRoleCandidates`
обслуживает начальный roster, замену группы, редактор и donor пополнения.
Новые позиции оплачиваются как `ANTI_TANK` (default 20 supplies каждая).
Easy и FIA сохраняют прежние роли. Stock Easy сохраняет также прежний US
fallback: в штатном каталоге отсутствует `Character_US_AT.et`; исправленный
выбор доступного `Character_US_LAT.et` применяется только к Medium/Hard.
Сохранённые пользовательские шаблоны применяются после стандартного комплекта
и могут менять оружие; три ПТ — контракт состава по умолчанию.

В WCS+RHS на любой сложности USMC LAT, TL и AMG получают M2 Carl Gustaf:
один заряженный выстрел, без запасных. TL/AMG (`memberIndex` 6/7) сохраняются
как два дополнительных носителя. Всего три установки на Easy, пять на
Medium/Hard. Основное оружие, роли и стоимость пополнения не меняются;
stock, RHS-only и РФ не затронуты.
`AICF_WCSInfantryKit.SecondaryLauncher` выбирает точные роли USMC;
`AICF_WCSInfantryEquipment` добавляет оружие в свободный второй native primary
slot локального draft либо заменяет исходный disposable launcher по native
`WT_ROCKETLAUNCHER` и `IsDisposable`, включая варианты вне единственного M72A3
GUID. Reloadable launcher и оружие других классов не перезаписываются.
Валидатор требует точный M2CG, один заряд и ноль запасных. `[AICF][WCS][ARM_FAILED]`
разделяет отказ primary/spares и вторичного slot/replace/insert/readback;
включает concrete source, фактический secondary prefab, ammo и spare.
Общий WCS commit с authority/identity/rollback обслуживает
начальный roster, замену группы, donors и стандартный комплект редактора.
Повторный Apply не дублирует и не перезаряжает Carl Gustaf; пользовательский шаблон
по-прежнему применяется после default и может изменить комплект.

Состав теперь выбирает server `AICF_FIAGarrisonPlanner`: Easy без техники,
Medium — один БТР с лимитом десанта 2/4 (50/50), Hard — две случайные машины
и одна усиленная точка с 2 БТР + 1/2 танками. Недоступные танки заменяются БТР.
Готовые FIA templates десанта выбираются отдельно для каждой машины во всех
сценариях. Legacy tank/passenger flags больше не управляют составом.
Точные вероятности, catalog, подготовка radio graph и JIP snapshot:
[FIA_GARRISONS.md](FIA_GARRISONS.md). Поиск площадки
детерминированный возле дороги в пределах 120 м от базы (кандидаты от 100 м
к центру с шагом 20 м): ближайшая дорога в пределах 40 м от кандидата,
проекция на сам сегмент и ориентация вдоль
сегмента дороги, проверка поверхности, воды, OBB, свободного выезда, другой
техники и строительных reservations. Дорожная достижимость от флага базы не
требуется: flag origin может лежать вне сети. До spawn обязателен подходящий участок
патруля на той же дороге. Проверяется также запас сухой земли на 12 м
для разворота без обрыва/воды. При отсутствии места — повтор через
30 с; после создания entity повторный spawn запрещён. Чужая база до spawn
закрывает slot. Захват после spawn не снимает оборону и не пополняет потери.

После 64 неудачных дорожных кандидатов проверяются 64 стационарных площадки
в радиусе 40–100 м. Для них сохраняются surface/OBB/вода, строительные reservations,
место экипажа и повторная identity/clearance проверка; дорожный endpoint, выезд
и площадка разворота не нужны. `m_bStaticDefense` фиксируется при spawn,
`READY stationary=1` и `PATROL_HOLD reason=STATIC_DEFENSE` обозначают такой гарнизон.
Ему не выдаются waypoint и route teleport; возврат экипажа на места сохраняется.
Радиусы дорожного патруля 140/200 м не расширяются.

`ReserveCrewCapacity` один раз при initial plan добавляет к текущему AIWorld
лимиту верхнюю границу экипажей (16 на машину, как предел DiscoverSeats)
и запас по числу баз для строителей. Easy лимит не меняет. Событие
`FIA_GARRISON_CAPACITY` показывает previous/required/effective limits. Без этой
квоты полный Hard Everon упирался в 260 активных персонажей до посадки всех экипажей.
Квота не материализует план: дополнительные бойцы появляются только возле
native observers и уходят в штатную dormancy после их ухода, см.
[FIA_PROXIMITY.md](FIA_PROXIMITY.md). Vehicle entity и потери сохраняются.

Essential места остаются экипажу; доступные cargo seats заполняются готовым
шаблоном десанта до выбранного лимита. У танка все места essential. Ожидается
полный asynchronous roster, затем проверяется посадка каждого immutable member.
`READY` требует заполнения всех выбранных мест. После READY вышедшие живые водитель,
стрелок и командир возвращаются forced GetInVehicle на закреплённые места;
чужие occupants не вытесняются, погибшие не заменяются. Роли определяются
metadata compartment: PILOT/TURRET, attached turret и commander name/UI key;
у танка все места относятся к экипажу. Stock spawn queue сохраняет readiness
и бюджетные ограничения.

Для БТР с выбранным десантом Attack/Suppress либо threat state ALERTED/THREATENED запускает обычную
анимированную высадку пассажиров: маршрут приостановлен до завершения выхода,
высадка выдаётся при скорости не выше 1 м/с, по одному запросу каждые 2 с.
Десант остаётся защищать точку пешком и автоматически обратно не садится;
ему запрещены vehicle patrol move и native boarding. Три члена экипажа остаются
в машине. После выхода живые пассажиры переводятся в отдельный AI controller
без spawn и без нового force slot: тот же гарнизон хранит immutable entity IDs,
проверяет обе group identities и передаёт logical member в его proximity lifecycle.
Это не даёт пешим бойцам блокировать vehicle group activity. Обе группы используют
native budget/dormancy, постоянные AICF LOD pins для FIA отсутствуют.
Телепорт для боевой высадки не используется.

`AICF_FIAGarrisonPatrol` сначала продолжает текущую дорогу на участке до 70 м
по её polyline, меняя направление у границы района или после неудачи движения.
Если на текущей дороге нет подходящего участка, ищет достижимую дорожную точку
в 45–100 м от машины. Все цели остаются в пределах 140 м от неизменного центра
домашней базы. При физическом удалении
более 200 м приказывает возврат на исходную площадку. Waypoint создаёт/снимает
`AICF_VehicleTaskHandoff`; перед удалением он исключается из очереди группы.
Через 45 с без перемещения либо при пропаже waypoint выбирается следующий участок.
После двух последовательных сбоев без прибытия `AICF_FIAGarrisonRecovery`
пытается перенести ту же машину на 15–80 м дальше по локальному маршруту.
Возврат исходного члена экипажа также запрашивает перенос машины с последующим
возобновлением патруля. Кандидат обязан оставаться внутри 140 м от дома,
иметь пригодную дорогу для продолжения, сухую поверхность, свободные OBB и выезд.
PlayerManager проверяет controlled и main entities у исходной и конечной
позиции; DistanceXZ <= 50 м запрещает перенос, включая персонажа на высоте.
При возврате экипажа проверяется позиция бойца и машины. Перед каждой мутацией
повторяются authority, immutable identity, occupant/transition и player fences.
Техника переносится только при скорости не выше 3 м/с; скорость и вращение
обнуляются, waypoint снимается через handoff, новый выдаётся после settling.
Неудачный поиск повторяется через 10 с, успешный перенос имеет cooldown 30 с.
`AICF_FIAGarrison` фиксирует постоянный recovery ban для исходной vehicle
identity/generation при любом уменьшении здоровья машины (включая отдельные
hit zones), ранении/гибели essential crew, гибели исходного пассажира или
невозможности достоверно проверить исходный состав/damage. Плановая высадка
живого пассажира допускается. `AICF_FIAGarrisonIntegrity` наблюдает все hit zones
в hierarchy с появления машины и регистрации исходных members, включая
синхронный урон/ремонт между scheduler ticks. Первый reason сохраняется;
ремонт, лечение, patrol leg, retry и исчезновение игроков не снимают ban.
Допуск повторяется перед поиском позиции и перед transform/forced boarding,
в том числе после синхронных waypoint/queue callbacks. Ban не меняет CanDrive,
не создаёт replacement и снимает ожидание crew recovery у ходовой машины.
Ни lease, ни entity ID, ни состав гарнизона не сбрасываются.
При отсутствии местной дороги служба ждёт и повторяет поиск.
`AICF_FIAGarrisonMovementPolicy` принимает native failed movement только от
текущей группы/машины/waypoint. После синхронного invoker повторно проверяет
identity и leg; завершает старое действие и передаёт retry патрулю. Stock
`GetOutActivity` при неудаче такого маршрута не создаётся. Потеря водителя,
чужой occupant или уничтожение машины снимают маршрут, но не оборону выживших. Ограниченная его immutable members policy
в `SCR_AIUtilityComponent` сохраняет stock выбор оружия/цели, Attack/Suppress и
idle. Отклонённые действия завершаются, чтобы не блокировать новый приказ. Move/formation допускаются только от текущего identity-проверенного
локального waypoint с живым собственным водителем. Combat movement и произвольные
pursuit/retreat действия запрещены: движение по патрульному приказу отделено от
самостоятельного преследования цели. Штатный driver avoidance разрешён только
своему живому водителю: манёвр не дальше 25 м от машины и внутри 200 м от дома.
Без него два встречных гарнизона взаимно блокировали бы движение.
Native GetIn разрешён своему бойцу в собственную машину не дальше 25 м от него,
при свободном собственном месте и положении машины внутри 200 м от дома.
Оборона продолжается после гибели других членов экипажа. Игрок, чужая группа,
обычная FIA и дорожные патрули не подпадают под policy.
Отдельная защита stock `SCR_AIUpdateTargetAttackData` пропускает два threat
callback при пустой `m_Target`: проверка боя выявила null dereference в API
1.8.0.13. Эта защита действует для любого AI; при наличии цели вызывается
штатный обработчик без изменений. Stop отменяет pending
spawn и waypoint, снимает LOD pin и очищает registry; entity не удаляются этой службой.

События `FIA_GARRISON_PLAN`, `SPAWN_REQUESTED`, `READY`, `WAIT`, `RETIRED`,
`PATROL_LEG`, `PATROL_ARRIVED`, `PATROL_RETRY`, `PATROL_WAIT`, `RETURN`, `MOVE_FAILED`,
`SEAT`, `DESANT_DEPLOY`, `DESANT_EXIT`, `DESANT_TRANSFER`, `CREW_TELEPORT`, `VEHICLE_TELEPORTED`,
`RECOVERY_BLOCKED`, `PATROL_HOLD`, `PATROL_RESUME`
используют префикс `FIA_GARRISON_` и существующий канал `[AICF][STAGE3]`.
Контекст: `faction numeric_slot generation base vehicle group tank`.
Случайный состав и посадку проверяет `tests/fixtures/AICF_FIARandomGarrisonProbe.c`;
огневая эффективность и поведение в полном бою требуют отдельного verdict.

## Командование и пехота

- Stable sides — `US` и `USSR`, включая RHS/WCS mapping. При запуске
  `-aicfAICommanderMode BOTH|US|USSR` фиксирует автономных командиров на весь
  процесс; default — `BOTH`. Значения регистрозависимы, `NONE` недопустим.
- Сторона без ИИ сохраняет roster, economy, vehicles и victory state, но до
  приказа игрока находится в `AWAITING_PLAYER_COMMAND` и `SYSTEM_HOLD` на HQ.
- По умолчанию 10 slots на сторону, роли `6 ATTACK / 4 DEFEND / 0 RESERVE`.
  Infantry seed содержит одного бойца; желаемый состав — 10. Стартовый roster
  двух сторон — 20 бойцов, общий бюджет управляемых AI по умолчанию — 220.
- Командир оценивает допустимый radio-front по ценности точки, подходу живых
  бойцов, угрозам, готовности и уже выделенным силам. Распределение учитывает
  ручные приказы и назначения этого же цикла; высокая потребность допускает
  совместную атаку. Срочная оборона HQ/оспариваемой базы может использовать
  ATTACK через `AREA_SECURITY`; обычные смены сохраняют dwell/stable gates.
  Веса, источники данных и cooldown неудач: [ADAPTIVE_COMMANDER.md](ADAPTIVE_COMMANDER.md).
- Перед первым выходом и после полной замены автономная пехота ждёт казарму
  и полный заданный состав. Пополнение покупается побойцово в действующей
  казарме после физического подхода на 35 м. Обычный боец стоит 10 supplies,
  медик — 15, гранатомётчик/AT и пулемётчик/автоматчик — 20.
- Автоматическая очередь общая для всех казарм одной фракции; US и USSR
  независимы. Начатый отряд обслуживается до полного состава или отмены/timeout,
  затем выбирается ATTACK перед DEFEND/RESERVE, FIFO внутри ранга. Ручное
  пополнение сохраняет приоритет. Первый и последующие шаги ждут 5 секунд;
  девять вакансий — плановые 45 секунд, сверх которых идут подход, очередь,
  дефицит снабжения и задержки spawn/tick.
- AI ищет казарму текущей/соседней базы в пределах 500 м; переход к соседней
  базе допустим, если служба ближе боевой цели. Учитываются путь, запас, доход
  и спрос других визитов: [прогноз](RECRUITMENT_SUPPLY_PLANNING.md).
- Выстрелы или боевой урон в пределах 100 м запрещают набор до 30 секунд
  тишины. Ручная команда пополнения ищет ближайшую безопасную союзную казарму
  без автономного радиуса 500 м; после набора возобновляется прежний приказ.
- Командная карта поддерживает приказы по базам и `MOVE_AND_HOLD` в точку,
  ручное пополнение и возврат отряда ИИ. Server revalidation обязательна.
- Управляемые боевые группы и охрана FIA получают `EXPERT`. Атакующая пехота
  использует разные промежуточные подходы к общей цели; recovery сохраняет intent.

## Экономика, техника и строительство

Vehicle и economy subsystems всегда включены; CLI opt-out нет. Форма
«Снабжение» отправляет физические доставки между союзными базами по запросу
игрока. Автоматический выбор новых доставок отключён. Припасы списываются
при погрузке; груз, возврат и recovery обслуживаются существующей логистикой.
Несколько рейсов разрешены; отдельного лимита заявок и логистических машин нет,
общий бюджет AI сохраняется. Форма показывает последнюю заявку, карта — все рейсы.

Союзные маркеры «О» показывают отряды, «Л» — логистику. Позывной закреплён за
numeric slot, сохраняется после замены группы и реплицируется для JIP.

ИИ планирует малые/большие казармы, арсенал, лёгкий и тяжёлый depot. Stock
службы и очередь игрока исключают дублирование. Worker каждой базы достраивает
по очереди, возвращается к главной палатке и удаляется после 30 секунд простоя.
Обычный progress требует подхода, инструмента и item-use; строитель уязвим.
Если поиск малой казармы не находит площадку 120 секунд, принудительный путь
снимает требования коридора/пути worker и завершает оплаченный проект сам,
сохраняя проверки земли, воды, препятствий, ownership, supplies и дубликатов.

На Medium/Hard FIA патрулирует направленные связи radio graph на УАЗах с ПКМ: одна машина
с водителем и пулемётчиком на две точки захвата без HQ, округление вниз.

## Экипировка и появление

Карта → свой отряд → «Экипировка» редактирует шаблон конкретной позиции.
Он применяется к следующему созданному бойцу этой позиции; живой AI обновляет
комплект при безопасном посещении дружественного арсенала. После боя служба
оценивает реальный боезапас, сначала предлагает сбор существующих подходящих
предметов с близких тел, затем визит в действующий `ARMORY`. Вместимость,
совместимость, combat, authority и identity проверяются повторно. Подбор не
меняет сохранённый шаблон. Пополнение живого бойца бесплатно; найм остаётся
платным. Настройки, thresholds и ограничения — [EQUIPMENT_SERVICE.md](EQUIPMENT_SERVICE.md).
Серверная библиотека — `profile/AICF_Loadouts`;
launcher умеет импортировать её через `-LoadoutLibraryPath`, без старых bindings.

«Применить» назначает экипировку позиции, «Сохранить» записывает библиотечный
пресет; одинаковое имя в том же контексте обновляет один ID. Применение не
создаёт файлов, удаление библиотечного пресета сохраняет назначения.
«Роль всем отрядам» назначает numeric position всем десяти slots стороны.
Пресет отряда хранит десять позиций: применить роли, ввести отдельное имя
отряда, сохранить; в библиотеке «[Отряд]» применяется одной кнопкой. Для
редактирования повторить сохранение под тем же именем. Администратор может
выбрать противника, включая отдельный вход на карте Co-op; обычный игрок —
свою сторону. Authority, revisions, persistence и проверки:
[LOADOUT_PRESETS.md](LOADOUT_PRESETS.md).

В обоих основных оружейных слотах каталог фильтруется по классу оружия.
Выбранная категория сохраняется между этими слотами, сочетается с источником
и поиском; «Всё оружие» возвращает полный список совместимых предметов.
Для карманов остаются прежние категории содержимого; для кобуры и обвесов —
native контекст. Правила классификации: [LOADOUT_WEAPON_CATEGORIES.md](LOADOUT_WEAPON_CATEGORIES.md).

При открытии одежды/разгрузки редактор по умолчанию показывает предметы всех
её карманов и вложенных подсумков одним списком. ПКМ удаляет выбранный предмет
из его настоящего кармана; Undo и Save используют прежний рецепт. Строки
добавления в конкретные карманы идут после содержимого. «Крепления» возвращает
обычную настройку самих подсумков, а «Содержимое» — общий список. Оружейные
обвесы остаются отдельной страницей. Технические границы и проверки:
[LOADOUT_CONTENTS.md](LOADOUT_CONTENTS.md).

На экране появления и возрождения доступны штатный `Default loadout` и
личный «Мой пресет». Рецепты хранятся в `profile/AICF_PersonalLoadouts` по
backend identity, стороне и content profile. Без backend identity сохранение
недоступно. Новый server profile не наследует рецепты автоматически.
Каталог, content policy, blacklist и вложенное содержимое проверяются на
сервере при сохранении, выборе и выдаче; неуспешный rollback блокирует spawn.

После смерти можно выбрать живого ИИ своего отряда и «Принять управление».
Передаётся существующий персонаж с его снаряжением; штатный respawn timer остаётся.
Rank policy снимает player-rank gates через `GENERAL`/XP floor; остальные
проверки покупки и размещения сохраняются. RU используется при `ru_ru`,
для остальных языков — EN; источники локализации ищи через
`tools/lib/AICFLocalization.Common.ps1` и `tools/Build-AICFLocalization.ps1`.

## Победа и замена отряда

`AICF_VictorySystem` завершает матч, если у противника кончились тикеты **или**
сторона владеет всеми активными точками и нет активного захвата/оспаривания.
HQ и RELAY не учитываются. `AreEnemiesPresent` сам по себе победу не блокирует.
Пустой/перестраиваемый граф не даёт территориальной победы; одновременные
условия у обеих сторон не выбирают победителя произвольно. Stock countdown отключён.

Полная замена уничтоженного отряда по умолчанию стоит 1 тикет и 50 supplies
за seed прежнего slot. Выбирается ближайшая к последнему погибшему бойцу
допустимая союзная база с `ONLINE BARRACKS`, supplies и spawn point.
Fallback — последняя известная позиция живого участника. Без позиции или базы
отряд ждёт; неудача не должна расходовать ресурсы. Набор живого отряда стоит supplies.

Все AICF headers отключают session save (`m_eSaveTypes 0`); каждый запуск
начинает новую кампанию. Захват баз ускорен втрое при прочих равных.
