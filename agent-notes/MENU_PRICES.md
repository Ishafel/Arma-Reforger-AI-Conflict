# Цены штатных меню RHS и WCS+RHS

Issue [#33](https://github.com/Ishafel/Arma-Reforger-AI-Conflict/issues/33).
Политика находится в RHS integration (`AICF_RHSMenuPricePolicy`,
`AICF_RHSMenuPriceIntegration`); WCS дополняет её через
`AICF_WCSMenuPricePolicy`. Core и stock dependency graph не зависят от RHS/WCS.
Цены активны при `AICF_RHSContentProfile`, включая наследующий WCS profile,
на Arland, Everon и Everon North. Политика не меняет registry IDs, порядок,
traits, доступность услуг, faction filters или разрешения игрока.

Это стоимость заказа игроком в штатных меню. Расценки автоматического AICF
пополнения 10/15/20 supplies, тикеты и внутренние vehicle transactions не меняются.
Полный список проверенных позиций — [MENU_PRICE_TABLE.csv](MENU_PRICE_TABLE.csv):
67 групп (20 USMC, 47 MSV) и 122 машины WCS, из которых 48 общие с RHS-only.
Столбцы сохраняют полный prefab/GUID, faction, исходный index, цены до/после,
численность/роли группы и измеренные compartments/weapon resources машины.

## Пехота

Используется фактический `m_aUnitPrefabSlots` каждой группы, включая USMC desert,
MSV Demiseason/Summer/Flora/VSR и пять доступных ambient Summer групп.
Цена группы — сумма всех членов; неизвестная роль или пустой roster сохраняет
native цену целиком. Камуфляж не влияет на стоимость. Численность и роли не
подменяются названием группы или составом десятиместного отряда AICF.

| Роль prefab | Supplies за бойца обеих сторон |
|---|---:|
| Rifleman, SL, TL, SR, AMG, AAT, Spotter | 50 |
| MG, AR, GL, Marksman, Medic | 75 |
| AT, LAT, Sniper | 100 |

USMC раньше стоили 150 за бойца; RF группы преимущественно имели 2–3 supplies
за целую группу (два LAT исключения — 300). Новая шкала оценивает штатную роль,
а не каждую единицу inventory. `_Random` остаётся той же ролью. Индивидуальный
CHARACTER filter RF содержит 182 prefab без CAMPAIGN budget; это не ещё 182
подтверждённых платных hire entries, их бюджеты не переписываются.
Комплекты AICF/WCS, выдаваемые управляемым отрядам после spawn, не считаются
автоматически комплектами штатного заказа игрока.

mobile assembly, лёгкие машины и UAZ Kornet 675. Неизвестный prefab получает
native цену. В таблице места — все фактические compartments, а не обещанное
число десантников: у отдельных модов командир/заряжающий помечен `CARGO`.

Основание — установленные prefabs, actual weapon entities/compartments и
ресурсы боеприпасов/ERA, снятые probe 13.10.2026 на 1.8.0.13,
RHS Status Quo 0.16.5237 (content packs 0.16.5236), WCS 8.3.0.
Weapon traversal включает также оружие в inventory; ручные гранаты/запасной
РПГ не считаются установленной башней. Наличие ARAT/Kontakt/BUSK подтверждает
различие комплектации, но не численную эквивалентность брони. Пробитие, TTK,
живучесть экипажа и эффективность в бою не измерены. Эти цены — балансная
политика на основе доступных классов и оснащения, не результат combat benchmark.

## Границы интеграции

`CAMPAIGN` нормализуется в возвращаемых бюджетах UIInfo и
`SCR_EntityCatalogSpawnerData.GetSupplyCost()`. Остальные budgets сохраняются.
Для группы native `GetEntityBudgetCost` пуст: server preflight использует
children, entity core списывает `GetGroupBudgetCost`, UI/refund читает total.
Каждый из этих путей получает полную цену ровно один раз. Vehicle own содержит
цену, children не добавляет второй CAMPAIGN. Native spawner debit и refund
продолжают получать стоимость из тех же штатных источников. Штатные процент
возврата и условия refund action не меняются.

UIInfo привязывается к конкретному prefab при чтении component source и
при получении live component info. Источники удерживаются Resource references
до `OnGameEnd`, затем очищаются. Цена spawner вычисляется лениво: InitData
может происходить до выбора content profile; active profile проверяется при
каждом чтении. Нет RPC, replicated price state или обхода server validation.

Native `SCR_EntityBudgetValue.MergeBudgetCosts` может изменить объект первого
бюджета в исходном массиве при повторяющемся типе. Поэтому binding читает
неизменяемый snapshot из исходного контейнера и добавляет копии в массив
вызывающего кода; getter не используется для подготовки snapshot.
Повторные чтения и массив с уже накопленной ценой проверяются отдельно.
Нельзя возвращать shared budget objects или менять installed resources.
