# Тактика пеших противотанковых бойцов

`Orders/AICF_AntiTankPolicy.c` содержит узкие adapters штатных
`SCR_AICombatComponent`, `SCR_AICombatMoveLogic_Attack` и
`SCR_AIGetAimErrorOffset`. API сверено с Script Diff `1.8.0.13`.

Политика применяется только на authoritative server при активном AICF controller:
живой пеший AI, выбранный `WT_ROCKETLAUNCHER`, текущая вражеская цель типа
`UnitType_VehicleMedium` или `UnitType_VehicleHeavy`. Игрок, посадка/высадка,
экипаж, пехотная цель, самолёт, устаревший target и другие типы оружия проходят
штатную цепочку. Общий `AISkill`, perception, threat memory, свойства боеприпасов
и strategic waypoint не меняются.

## Параметры

Константы находятся в `AICF_AntiTankPolicy`; отдельного пункта меню или CLI нет.

| Параметр | Значение | Смысл |
|---|---|---|
| `ENGAGEMENT_RANGE` | 400 м | Максимальная рабочая дальность **уже выбранного** РПГ против распознанной бронецели |
| `AIM_WINDOW_SECONDS` | 10 с | Окно остановки при видимой цели в разрешённом диапазоне без союзника на линии огня |
| `REPOSITION_WAIT_SECONDS` | 2 с | Ожидание перед поиском новой позиции при отсутствии условий для выстрела |
| `MOVE_SECONDS` | 2 с | Продолжительность штатного movement request без найденного укрытия |
| `COVER_SEARCH_METERS` | 15 м | Радиус поиска укрытия для короткого перемещения |
| `MAX_AIM_TOLERANCE` | 0,25° | Верхний предел допуска наведения; штатный допуск дополнительно умножается на 0,5, сохраняется штатный минимум |

Оба accessor дальности возвращают согласованное значение. Минимальная безопасная
дистанция и `directDamage` остаются штатными; если минимум не ниже 400 м,
дальность не подменяется. Native weapon/target selector,
проверки баллистической траектории, видимости, боеприпаса, готовности оружия и
friendly fire не обходятся. В stock случайная ошибка aim offset для РПГ уже
равна нулю: изменяется допуск наведения, а не глобальный разброс.

## Движение

При `THREATENED`, `HOLD_FIRE` или `ShouldKeepFormation()` используется штатное
движение. Для остальных подходящих атак выбирается короткое перемещение:
сначала поиск укрытия с видимостью цели, затем разрешённый выход без укрытия,
если текущая позиция не позволяет выстрелить. Направление к цели ограничивается
штатным resolver waypoint/защиты базы. При готовой линии огня после окна
прицеливания поиск идёт вокруг, а не прямо к бронетехнике.

Во время движения прицеливание выключено, в конце включается; конечная поза —
`CROUCH`. Reload/hide, выход из подавления, обход союзника и отступление при
слишком малой дистанции остаются в штатном приоритетном дереве. Это не новый
controller приказов и не гарантированный цикл «один выстрел — возврат в ту же
точку»: перемещением владеет stock combat move state. Новых callbacks и таймеров
в production нет.

## Проверки

`tests/contracts/Test-AntiTankContracts.ps1` проверяет authority, player/foot/
target/weapon gates, сохранение приказов и штатных checks; отрицательные мутации
должны отвергаться. `tests/fixtures/AICF_AntiTankProbe.c` устанавливается только
в изолированный Core stage; CLI `-aicfAntiTankProbe 1`. Проверка фиксирует
native/effective range, выбор РПГ и событие `OnWeaponFired` с projectile против
гарнизонного БТР. Неуязвимость стрелка, перенос участников и фиксация физики
мишени в `COLLISION` принадлежат fixture.

Static, Workbench и фактическая стрельба — разные gates. Дальность выстрела
не доказывает попадание; случайный единичный выстрел не подтверждает hit rate.
Фактические результаты и ограничения приведены в [TESTING.md](TESTING.md).
