# Проверка окна техники игроком

Статус: **NOT RUN**. Terminal UI-tree/model, native occupants и client/JIP
readback проверяют состояние, но не внешний вид, ввод мышью и читаемость.
AGENTS запрещает агенту GUI automation, screenshots и video. Этот список не
заменяет обязательные compile/runtime gates; текущий общий результат — FAIL.

`NOT RUN` здесь относится к наблюдению игроком: читаемости, clipping, полноте
rendered mesh, физическому вводу и видимой согласованности действий. Упомянутые
в пунктах11–12 выход/возврат, crew deferral, same vehicle, следующий приказ,
survivor identity и неизменное здоровье имеют отдельные terminal/native gates;
запрет GUI не делает эти функциональные критерии непроверяемыми.

Использовать fixture-free сборку и точный commit/source manifest, указанные
в последнем отчёте #78. Не подключать stage из Scenario/MultiSquad probes.
Stock server и direct-connect client запускать в двух терминальных сессиях
через `tools/Start-AICFRuntime.ps1`, сохранив manifests и полные stopped logs.
Для игрока USSR выбрать server `-AICommanderMode US`; для игрока US —
`-AICommanderMode USSR`. BOTH передаёт обе стороны AI и не подходит для
проверки командования игроком. Client получает точный свежий server profile.

Проверить отдельно за USSR на УАЗе и за US на Humvee:

1. На карте выбрать свой отряд и открыть «Техника». Проверить читаемость
   названия, стоимости, статуса, списка бойцов и мест при реальном разрешении
   экрана. Зафиксировать разрешение и масштаб интерфейса текстом.
2. Переключить свою сторону/CIV и категории. Убедиться визуально, что список
   обновляется, hover выделяется и возвращается после ухода указателя.
3. Выбрать машину: preview виден, не обрезан, соответствует выбранной модели;
   смена модели обновляет preview и реальные места. У невооружённого УАЗа
   отсутствует место стрелка; у вооружённого варианта оно появляется.
4. Ползунком выбрать состав 1, 5 и 10; проверить подпись значения, крайние
   положения, перетаскивание и несовместимость состава с числом мест.
5. Назначить водителя/пассажиров, изменить и снять назначение. Проверить
   понятное сообщение о свободных местах и бойцах без места.
6. Save → Load → Update → Delete: проверить названия и видимое состояние
   черновика. Save не должен выдать машину. «Автоматика» должна снять ручное
   назначение, сохранив несохранённый черновик и рассадку в открытом окне.
7. При уменьшении состава 10 → 1 проверить текст подтверждения: Cancel
   сохраняет состав; повторное явное подтверждение оставляет назначенного
   водителя, остальные возвращаются. Проверить отсутствие наложения текста
   и доступность кнопок. Не подтверждать сокращение до прочтения предупреждения.
8. Применить совместимый preset, наблюдать посадку и ожидание. Задать удалённую
   точку, наблюдать движение, высадку и следующий маршрут. Переоткрыть окно
   после позднего подключения и сравнить видимое подтверждённое состояние.
9. **NOT RUN — новые настройки поведения.** В «Техника» проверить названия и
   читаемость вариантов TRANSPORT/COMBAT, поле N и исходное значение300м.
   Выбрать COMBAT/437, сменить модель и убедиться, что несохранённый ввод
   сохранился. Ввести49,1001 и нецелое значение: Save/Apply должны показывать
   понятный отказ. Проверить границы50/1000, отсутствие наложения подписей и
   возможность редактирования поля мышью/клавиатурой.
10. **NOT RUN — сохранение и позднее подключение.** Сохранить COMBAT/437,
    загрузить, обновить на TRANSPORT/300, переоткрыть окно; применить и сравнить
    подтверждённое состояние на поздно подключившемся клиенте. Save сам не
    выдаёт автомобиль. Проверить видимые подписи и значения, а не только
    наличие settings в terminal readback.
11. **NOT RUN — поведение в бою.** На fixture-free сборке наблюдать реальную
    угрозу рядом с TRANSPORT: весь живой способный отряд выходит, после боя
    возвращается в ту же машину. У COMBAT выходит десант, исправные водитель
    и стрелок продолжают сражаться вместе с ним. При настоящей потере crew
    замена COMBAT ожидает окончания местного боя; при невозможности продолжать
    движение отряд переходит к пешему порядку. Отметить видимые задержки,
    рассогласование и повторные посадки. Не добавлять fixture/лечение/воскрешение
    для получения нужного исхода.
12. **NOT RUN — возврат, выжившие и короткая коррекция.** После пешего эпизода
    выдать новый приказ дальше N, наблюдать возврат в прежнюю машину и движение;
    для TRANSPORT проверить такой приказ также при продолжающейся угрозе.
    Если original недееспособный боец естественно пришёл в сознание после замены
    водителя, проверить, что он получает свободное Cargo либо весь отряд
    продолжает пешком, а способного бойца не бросают. Разрешённая короткая
    принудительная посадка/высадка может быть видна игроку. Описать наблюдение
    текстом; по внешнему виду не утверждать точную дистанцию, health, identity
    или корректность clearance — это отдельные terminal проверки. Без такого
    естественного эпизода соответствующая часть остаётся NOT RUN.

Передать текстовый результат для каждого пункта: PASS/FAIL/NOT RUN, сторона,
модель, commit, разрешение/масштаб и конкретное расхождение. До получения
этого результата все пункты остаются NOT RUN. Отдельно анализируются полные
server/client logs: визуальный PASS не отменяет native persistence/resource FAIL.

Причина NOT RUN для новых пунктов та же: агенту доступен terminal workflow,
но запрещены GUI automation и визуальная запись. Hidden UI/settings probes
не доказывают читаемость, работу указателя и восприятие совместного боя.
Новые controlled behavior/cleanup probes и focused roster contracts описаны
в [VEHICLE_BEHAVIOR.md](VEHICLE_BEHAVIOR.md); их compile/runtime итог подводится
отдельно. Добавление этого checklist не снимает строгие blockers #78 и не
является объявлением ACCEPTED.

## Native camera/resource blocker — 29.10.2026

Текущие game/server/Workbench binaries имеют version1.8.0.13; несовпадение
версий этим исследованием не обнаружено. Avatar-only control с настоящим
player entity, но без вызовов editor/preview builders AICF, дал native0/0/0,
полные stopped logs/fatal0/leaks0 и0 camera overlaps. Его70 exact error groups
составляют baseline остальных resource/font/texture ошибок, а не whitelist.

Отдельный минимальный native-only control содержит только
`AICF_VehicleNativeControl.c`, `AICF_PersistenceReconnectTrace.c` и
`AICF_StockLightingNativeControl.c`, без всех production Scripts AICF. Он создаёт
штатный `InspectionPreview` world/camera и через `SpawnEntityPrefab` загружает
неизменённый `InventoryPreviewWorld.et` с GUID4391FE7994EE6FE2. На1.8.0.13 native0/0,
scene_present1/private1/same_world1; внутри этого единственного native spawn
воспроизводятся все8 HDR/SMAA `Overlapping PP effects ... overwrites empty effect`.
Это терминальная проверка конструктора, не визуальная проверка изображения.

cached mesh миру manager и его удаление вместе с manager. Без доказательства

вид и полный rendered mesh остаются визуальными NOT RUN по прежним правилам.
